# Spec Delta

## Purpose

客户端主对话界面的对话线程：呈现用户与 agent 的消息流、思维链与思考过场，并在流式输出过程中保持阅读者的位置不丢失。

## ADDED Requirements

### Requirement: 消息线程呈现

线程 SHALL 按时间顺序呈现用户消息与 agent 回复，两者在视觉上明确区分：用户消息靠右、使用次级填充气泡；agent 回复无气泡、直接排版正文。agent 回复的 Markdown SHALL 被渲染为富文本，其中 fenced 代码块 SHALL 以带复制入口的代码块样式呈现。代码块、参数、ID 等 SHALL 使用等宽字体，正文使用设计中文字体与行高。

#### Scenario: 用户与 agent 的回合

- **WHEN** 用户发送一条消息并收到 agent 回复
- **THEN** 线程依次呈现靠右的用户气泡和左对齐的 agent 富文本回复

#### Scenario: 回复包含代码

- **WHEN** agent 回复中包含 fenced 代码块
- **THEN** 代码以等宽字体、带复制按钮的代码块呈现，且视觉风格符合设计令牌而非渲染库默认主题

### Requirement: 流式滚动纪律

线程 SHALL 在新回合开始（用户消息追加）时将该消息锚定在视口顶部附近，并在其上方保留上一回合的一小段窥视内容。当且仅当阅读者位于最新内容边缘时，视口 SHALL 跟随流式输出滚动；阅读者向上滚动后，视口 MUST NOT 因新内容到达而移动，并 SHALL 提供回到最新内容的可见入口。

#### Scenario: 新回合锚定

- **WHEN** 用户发送新消息
- **THEN** 该消息稳定到视口顶部附近，上方保留上一回合的部分内容，回复在其下方流式展开

#### Scenario: 阅读者不跟随

- **WHEN** 回复正在流式输出且阅读者向上滚动阅读历史
- **THEN** 视口保持原位，出现回到最新内容的按钮；点击后视口跳到最新内容并恢复跟随

### Requirement: 思维链呈现

agent 的思考与工具步骤 SHALL 以一条可折叠摘要行呈现于回复正文之前。摘要行 SHALL 反映整体状态（进行中 / 完成 / 含失败）；运行中摘要自动展开，结束后自动收起且步骤的展开状态被保留。每个步骤 SHALL 以一行呈现，图标与文案区分进行中、完成、失败三种状态，文案时态与状态一致；失败步骤 SHALL 以内联错误详情呈现并可展开查看。

#### Scenario: 运行中的思维链

- **WHEN** agent 正在执行思考或工具步骤
- **THEN** 摘要行显示进行中状态并自动展开，各步骤实时更新其状态与时态文案

#### Scenario: 完成后的思维链

- **WHEN** 所有步骤完成且回复正文开始输出
- **THEN** 摘要行收起为完成摘要（含步骤数，失败时含失败数），阅读者可手动重新展开查看步骤

#### Scenario: 步骤失败

- **WHEN** 某个工具步骤失败
- **THEN** 该步骤显示失败状态与内联错误详情，摘要行在完成摘要中计入失败数

### Requirement: 思考过场

在 agent 回复的第一个可见内容（思维链步骤或正文）到达之前，线程 SHALL 在回复占位处显示循环思考动画；第一个内容到达后动画消失。该动画 SHALL 尊重系统减少动效偏好。

#### Scenario: 等待首个输出

- **WHEN** 用户消息已发送、agent 尚未产生任何可见输出
- **THEN** 回复位置显示循环思考动画；首个内容到达时动画被内容替换

### Requirement: 界面状态完备

线程 SHALL 覆盖以下状态：空会话（居中引导与建议提问）、历史加载（向顶部追加历史时阅读位置不跳变）、发送失败（用户消息标记失败并可重试）、回复中断或错误（内联错误与重试入口）。

#### Scenario: 空会话

- **WHEN** 当前会话没有任何消息
- **THEN** 线程区域显示居中引导文案和可点击的建议提问，点击建议提问等效于发送该文本

#### Scenario: 加载历史

- **WHEN** 更早的历史消息被追加到线程顶部
- **THEN** 阅读者当前查看的内容保持原位，不发生跳动

#### Scenario: 发送失败

- **WHEN** 消息发送失败
- **THEN** 该消息呈现失败标记与重试入口，线程位置不移动

### Requirement: 线程状态独立于界面挂载

每个对话线程的状态 SHALL 由独立于界面组件生命周期的 store 持有，并由缓存注册表统一管理。界面卸载 MUST NOT 终止该线程的事件折叠与流式接收；重新挂载 SHALL 同步呈现该线程的最新状态，不出现加载闪烁。流式进行中的线程 MUST NOT 被缓存驱逐；仅用户显式停止可终止流。

#### Scenario: 离开后再返回

- **WHEN** 用户离开一个正在流式输出的线程界面，之后重新进入
- **THEN** 界面立即呈现包含离开期间全部新内容的最新的状态，无加载过程

#### Scenario: 缓存驱逐纪律

- **WHEN** 缓存注册表需要驱逐以控制内存占用
- **THEN** 仅驱逐未挂载且无进行中流的线程

### Requirement: 可访问性与动效降级

线程容器 SHALL 暴露日志语义（新消息可被屏幕阅读器以追加方式播报），所有消息操作 SHALL 可键盘到达并有无障碍名称。全局 SHALL 尊重减少动效偏好：布局与空间动画降级为瞬时或淡入，思考过场降级为静态指示。

#### Scenario: 减少动效

- **WHEN** 系统开启减少动效偏好
- **THEN** 线程不出现弹簧或循环位移动画，状态反馈以淡入或瞬时变化呈现

### Requirement: 视觉令牌遵从

线程及输入区的全部视觉 SHALL 使用项目设计令牌：唯一签名色仅用于主操作、激活态与关键强调；磨砂半透明仅用于浮层（菜单、tooltip、滚动按钮等）；主内容区与气泡为实色；中西文与等宽字体按令牌分配；正文及占位文本对比度不低于 4.5:1。

#### Scenario: 样式审查

- **WHEN** 对完成的界面进行视觉审查
- **THEN** 不存在渐变、发光装饰或非令牌色值，签名色只出现在主操作与激活态，磨砂仅出现在浮层
