# Spec Delta

## Purpose

客户端对话界面与数据来源之间的网关：定义前端自有的对话 DTO 与传输接口，使界面代码不直接依赖后端契约或具体传输方式（mock / Tauri IPC / Web 接口），切换传输实现时界面调用方代码不变。

## ADDED Requirements

### Requirement: 前端自有 DTO

网关 SHALL 定义前端自有的对话数据类型（事件、消息、用量、元信息等），其字段由传输适配器与桌面运行时事件在语义上一一映射，类型独立命名、独立演进。界面代码 MUST NOT 直接依赖后端类型或传输协议的报文格式。DTO SHALL 支持思考步骤与工具调用的事件表达。

#### Scenario: 字段等价

- **WHEN** 对照桌面运行时的每种事件（开始、增量、部分完成、用量、完成、错误终止）
- **THEN** 前端 DTO 存在语义对应的变体，且映射关系在代码中被显式声明与注释

### Requirement: 传输无关的网关接口

网关 SHALL 以接口形式暴露对话能力：提交一轮对话输入并以事件流形式接收响应事件，以及中止当前响应。界面状态管理 SHALL 只依赖该接口与 DTO，不感知事件来自 mock、Tauri IPC 还是 Web 接口。

#### Scenario: 替换传输实现

- **WHEN** 将网关的 mock 实现替换为真实传输实现（Tauri IPC 或 Web 接口）
- **THEN** 界面与状态管理代码不需要修改，仅替换接口的实现绑定

### Requirement: 事件流折叠为界面状态

网关消费方 SHALL 把事件流折叠为线程所需的界面状态：消息列表、各回复的输出部分、思维链步骤状态、整体运行状态与错误。折叠逻辑 SHALL 与渲染分离，可独立于界面测试。

#### Scenario: 完整流式回合

- **WHEN** 网关依次产出开始、若干增量、用量与完成事件
- **THEN** 界面状态依次呈现思考过场、正文增长、最终完整回复与正常收尾

#### Scenario: 流中错误

- **WHEN** 事件流以错误终止
- **THEN** 界面状态保留已输出内容并标记该回合失败，提供重试所需的信息

### Requirement: Mock 实现

网关 SHALL 提供 mock 实现：以脚本化数据按真实事件序列与时序（可配置的逐段延迟）产出事件流，覆盖正文流式、思维链步骤、失败与停止场景，使界面全部状态无需后端即可验收。

#### Scenario: mock 驱动全部状态

- **WHEN** 使用 mock 网关运行界面
- **THEN** 空态、流式、思维链展开收起、步骤失败、发送失败与停止等场景均可演示
