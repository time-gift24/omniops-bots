# 08 · 前端现状与缺口

> 串讲重点：沿用已有页面与视觉风格，把资源发布、同步装配和任务交付补成完整流程。

## US

1. 作为串讲参与者，我能直接对照现有页面，分清已经可用的交互与尚待接通的业务。
2. 作为使用者，我能知道资源来自本地还是官方、使用哪个版本，以及任务执行和结果交付到了哪一步。
3. 作为运维人员，我在已有 Skill、Agent 页面完成编辑、实验与发布，不需要另一套管理后台。

## 简要设计

现有前端已经具备左侧导航、会话、Agent 配置、Skill 文件阅读与编辑、右侧工作台。继续沿用**暖灰底色、绿色强调、细边框、轻量圆角，以及 Geist / MiSans 字体**。新增功能融入这些页面，不重做导航体系。

普通 Web 启动使用演示适配器；桌面入口另有 Tauri 本地运行时适配。因此，下列截图代表**已有 Web 的真实页面与交互**，其中资源和执行数据为演示内容，不能据此认为远端发布、同步或任务交付已经接通。

![现有 Web 工作区：左侧导航、中央会话和右侧工作台](./assets/screenshots/00-workspace.png)

*沿用这套页面框架；连接、同步和任务状态应放在相应操作附近。*

## 服务端

- 提供已有登录身份与运维权限，客户端据此展示写入入口，服务端继续执行权限校验。
- 提供官方草稿修订、发布版本、版本清单与物料下载；Skill 发布联动受影响 Agent。
- 通过 WebSocket 调用与取消任务，接收状态、结果、快照并确认收到。
- 提供桌面更新清单和整包下载。发布、同步、MCP 连接与更新的真实状态需要接入数据，不能只补按钮。

## 客户端

MVP 优先补齐三组完整流程：

1. **资源身份与发布**：区分本地和官方；在 Skill、Agent 现有页面补版本、只读、草稿实验、运维上传和手填标签发布。
2. **同步与开始运行**：在新会话入口展示版本核对、缺失物料下载和工具检查；准备失败说明原因，准备完成固定快照。
3. **执行与结果交付**：复用会话和任务横条，补远端只读、执行记录、快照、结果待确认与重启中断状态。

桌面更新另补轻量设置入口，展示检查、下载、待安装和失败状态；不用扩大为独立更新中心。

## 详细设计

| 对应章节 | 沿用已有页面 | 需要补的交互 | 依赖的接入 |
| --- | --- | --- | --- |
| 00 总体 | 导航、会话、工作台 | 登录身份、运维权限、连接与重连状态 | 现有 Token、权限和 WebSocket |
| 01 Skill | 文件树、阅读、编辑、预览、保存草稿 | 本地/官方标识、完整包编辑、版本轨迹、官方只读与复制本地、选 Agent 实验、上传与联动发布 | 包快照、草稿修订、发布与实验装配 |
| 02 MCP | Agent 内 MCP 勾选与能力详情 | 配置或引用、官方只读、连接失败原因 | 随 Agent 同步配置、真实远端连接与工具调用 |
| 03 builtinTool | Agent 的工具勾选清单 | 缺失工具提示、更新入口、实际工具清单 | 本机工具目录和运行前检查 |
| 04 Agent | 名称、描述、系统提示词、能力勾选和调试 | 本地/官方分组、新建本地 Agent、固定 Skill 版本、内容 ID、发布标签、从 Agent 发起会话 | 官方草稿发布、确定装配和会话快照 |
| 05 桌面更新 | 当前没有更新入口 | 当前版本、检查、说明、下载进度、待安装、空闲时手动安装与错误提示 | 整包更新、验签、安装与任务互斥 |
| 06 同步装配 | 通用加载中、失败和重试样式 | 核对版本、缺包下载、缓存版本、失败原因；已有会话沿用原快照 | 清单、按需下载、本地多版本保存与装配 |
| 07 执行恢复 | 流式对话、工具过程、任务横条、忙时限制 | 远端会话只读、调用 ID、起止时间、结果/错误、快照、待确认/已交付、超时和中断未知 | 持久化、确认与补传、服务端取消、兜底超时 |

![现有 Agent 页面：配置、能力选择与系统提示词](./assets/screenshots/04-agent.png)

*这里补官方身份、固定版本和发布入口。现有“调试”只进入 Agent 调试会话，还不是“临时装配当前 Skill 草稿”的实验流程。*

![现有 Skill 页面：文件树、正文阅读与编辑入口](./assets/screenshots/01-skill.png)

*这里补版本轨迹、完整包操作、选择 Agent 实验和发布。现有“保存草稿”保存的是本地单文件内容，尚不是服务端草稿修订。*

串讲时避免三个误解：

- **旧审批演示不作为本期新增需求。** 页面已有“操作前先确认”和审批状态，后续按已确认的 MVP 流程调整；不增加发布审核。
- **调试不等于草稿实验。** 实验需要把当前完整草稿临时装配给选中的 Agent，并固定快照，不能仅打开原 Agent 的调试会话。
- **没有更新入口是前端缺口。** 这不等于断言整个仓库没有底层更新代码；本次审查限定在现有 Web 页面与接入接口。
