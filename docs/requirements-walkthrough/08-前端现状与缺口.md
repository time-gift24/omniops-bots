# 08 · 前端现状与缺口

> 串讲重点：线上用户在服务端 Console 操作，客户端后台执行服务端 Agent 下发的任务。本章区分已有运维调试桌面与待完成的线上基础状态／维护界面，说明各自完成情况及服务端接入缺口。

## US

1. 作为串讲参与者，我能结合页面理解完整业务流程，并知道各项能力的完成情况。
2. 作为线上用户，我在 Console 发起业务、查看任务状态与结果；客户端日常后台运行，本机只需提供连接等基础状态与必要维护入口。
3. 作为运维人员，我在调试桌面查看资源来源、版本、执行与交付详情，并在 Skill、Agent 页面完成编辑、实验与发布。

## 简要设计

现有前端是运维调试桌面，由左侧导航、中央调试页面与右侧工作台组成。会话承载本地实验与调试交互，Agent 页面管理装配，Skill 页面管理文件包与版本，工作台展示浏览器和执行过程。它不作为线上用户入口。线上业务入口在服务端 Console；客户端后台接收服务端 Agent 的任务调用，面向线上用户的本机界面仅提供连接等基础状态与必要维护入口，这部分仍待实现。视觉沿用 **Cognacta / Arc 的中性色底、绿色强调、细分隔线、轻量圆角，以及 Geist / MiSans 字体**。

本章工作区截图保留历史 macOS 运维调试桌面实拍，右侧为旧 Agent CEF 模式；当前 Agent 使用外部 Chrome，内嵌 CEF 改为运维手动浏览器，两者独立；后面的资源管理截图为当前共享前端的 Web 页面，使用演示数据。下表依据当前本地 LangGraph 客户端实现区分已具备能力与剩余接入。

## 客户端

已有及计划中的运维调试桌面围绕四组流程组织；线上用户的业务发起、取消和结果查看由 Console 承接：

1. **资源身份与发布**：Skill、Agent 页面区分本地与官方资源，管理版本、只读配置、草稿实验、运维上传和手填标签发布。
2. **同步与开始运行**：在新会话入口展示版本核对、缺失物料下载和工具检查；准备失败说明原因，准备完成固定快照。
3. **执行与结果交付**：仅供运维按会话分别展示运行状态、执行过程和停止入口；工作台切换对应会话的 Chrome 状态，通过「显示 Chrome」查看真实页面，切换不改变后台运行目标。不同会话可并发，同会话运行中、其页面正在手动导航或总容量已满时显示忙；服务端会话只读，执行记录呈现快照、结果待确认与重启中断状态。
4. **故障诊断上传**：从执行记录选择指定 thread，查看 checkpoint 与材料清单，提交后以服务端持久保存的回执确认接收。

运维调试桌面的「设置 → 偏好设置」提供「并发任务上限」，默认 4，可保存 1～64 的整数；保存后立即用于新任务受理，下调不取消现有任务，重启后保留。读取失败提供重试，保存失败保留输入与原有效值。Web 演示只在内存中保存。线上用户基础状态／维护入口中的桌面更新计划展示检查、下载、待安装和失败状态，保留用户手动确认，尚未实现；处理连接、更新和必要验证不要求进入完整调试工作台。

完成情况与范围：

- **审批不属于本期 MVP 流程。** 真实本地运行不经过操作审批；旧截图和演示适配器中的审批内容不代表桌面执行流程，正式发布也无审核环节。
- **运维本地草稿实验已完成。** 先保存当前编辑，再选择 Agent 新建实验会话；运行时固定完整草稿，不修改模板 Agent 或已有会话。
- **Provider 首版已接入。** 设置页支持多个 OpenAI 兼容接入、模型与可选 Key，普通配置只存系统凭据引用；全局默认值与会话固定选择已接入。手动测试对已保存模型发送固定最小请求，15 秒总超时且支持取消，不读取会话或执行工具，保存配置不自动测试。Windows 凭据实机验收待完成，迁移与旧会话边界见第 11 章。
- **运维本地多会话并发已接入。** 每个 thread 固定浏览器页面；切换工作台不改变运行目标，停止仅作用于所选 run。真实 CDP 回归已覆盖一个页面导航阻塞时另一任务与脚本完成、独立取消、共享登录态及下一轮复用原页面；Agent 现在使用外部 Chrome，原生 CEF 只保留运维手动页；运维导航、地址历史、任务运行与 Chrome 聚焦的独立性已有回归覆盖。历史单会话截图不作为这些并发行为的验证依据。
- **本地会话持久化不等于 checkpoint 持久化。** `.sessions` 保存消息和装配快照，`.records` 保存运行证据；图状态已由 execution 使用原生 SQLite saver 单独保存，诊断导出与上传仍待实现，见第 09 章。
- **线上基础界面、服务端接入与桌面更新仍未完成。** 线上基础状态／维护界面、登录权限、官方同步/发布、WebSocket 任务与结果交付不能以本地调试链路通过作为完成依据；也不能把现有完整工作台直接交给线上用户作为业务入口。

## 详细设计

前端状态按入口区分：Console 展示线上任务状态与结果，本机基础界面展示连接等状态，运维调试桌面展示准备、逐条过程和交付证据。下面的本地手动场景仅用于调试，线上正常调用见 [00 章服务端 Agent 任务调用模型](./00-总体架构.md)；各模块的其他失败情况见对应章节顺序图。

### 运维调试开始：准备完成后进入本地会话

![运维手动调试会话的运行模型](./assets/runtime/00-manual.svg)

[打开顺序图：运维手动调试会话的运行模型](./diagrams/runtime/00-manual.html)

运维调试桌面先展示准备状态，准备完成后展示执行过程，结束后展示结果并允许下一轮输入。线上用户始终在 Console 操作，由服务端 Agent 调用后台客户端。准备或工具检查失败时停在失败状态，按同步与 builtinTool 章节的运行模型处理。

### 执行中断线：区分执行结果与交付状态

![断线继续执行与结果补传](./assets/runtime/07-disconnect.svg)

[打开顺序图：断线继续执行与结果补传](./diagrams/runtime/07-disconnect.html)

本机基础界面表达连接状态；任务连接断开时仍可后台运行，任务结束后可处于“结果待确认”，确认收到后转为“已交付”。客户端将状态与结果交给服务端 Agent，Console 更新线上用户可见的任务状态和结果；运维调试桌面可查看本地详细记录。连接恢复本身不触发重新执行。

## 服务端配合

线上 Console 与客户端各自界面的业务接入依赖以下服务端能力：

- 提供已有登录身份与运维权限，客户端据此展示写入入口，服务端继续执行权限校验。
- 提供官方草稿修订、发布版本、版本清单与物料下载；Skill 发布联动受影响 Agent。
- Console 承接线上业务发起、任务状态与结果查看及取消请求，由服务端 Agent 通过 WebSocket 以任务调用或取消客户端 Agent，接收状态、结果、快照并确认收到。
- 提供桌面更新清单和整包下载。
- 提供诊断上传身份与权限校验、指定 thread 材料接收、持久保存回执和运维只读查看；不因接收 checkpoint 启动原任务。
