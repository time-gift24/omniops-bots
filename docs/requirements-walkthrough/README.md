# OmniOps Bots · 客户端 MVP 需求串讲

**客户端是由服务端 Agent 以任务形式调用的本机后台执行端，线上用户的主体操作在服务端 Console 完成。** 用户在 Console 发起业务请求、查看任务状态与结果；服务端 Agent 编排任务，客户端 Node.js／LangGraph 在本机执行，经 Playwright 操作应用管理的外部 Google Chrome 并回传结果。线上客户端通常作为后台进程运行，只展示连接状态等基础信息。完整桌面用于运维调试，提供 Agent 与 Skill 的管理、编辑、本地会话和实验入口，另保留供运维手动操作的内嵌 CEF 浏览器；线上用户看不到这套调试桌面。

核心资产是受版本控制、持续演进的 **Agent 提示词与 Skill**。客户端把提示词、固定 Skill 版本、builtinTool 与 MCP 装配成可执行的 Agent；团队根据真实任务反馈按周迭代发布，保留不可变历史，新版从新会话生效。

本目录围绕线上后台任务、运维调试、资源管理和运行恢复展开，按「核心」「细节」两组组织：核心依次包含版本管理前置说明、服务端部署与持久化、客户端总体需求、A2A 任务执行与恢复，以及运维 Skill 模板与迭代；细节包含资源操作、运行恢复、维护和接口契约。第 10 章集中说明服务端需要提供的 API，第 11 章补充运维在本机预配置 Provider 与模型。00、08 章的工作台截图是运维调试桌面的历史实拍，包含实际被 Playwright 操作的内置 CEF 页面；使用本地测试模型和测试页面。这些截图不代表线上用户界面，也不代表当前外部 Chrome 与手动 CEF 的分工，不作为多会话并发验收证据。其他资源管理截图保留运维调试视图的 Web 演示界面，图片均可点击放大。

串讲时点击阅读页的「本章评论」记录本章意见，可编辑、删除和撤销删除。评论仅保存在当前浏览器，刷新后可继续查看；切换章节保留尚未提交的输入，但刷新前须保存。使用「导出全部评论」生成 Markdown 供会后整理。评论不会上传服务端，清理浏览器数据、换浏览器或移动阅读页路径可能无法再找到原记录，请及时导出。

本仓交付桌面客户端；第 10 章的服务端接口是外部系统配合契约。Node.js 是主后端，Rust 只保留桌面宿主、CEF helper 与 Collector。Node、Playwright、CEF 随包交付，Google Chrome 单独安装和更新；Rust 工具链为 1.92.0。

设计范围包含已具备的界面与尚未完成的能力，具体完成情况见第 08 章。后续章节的资源页面、本地会话和工作台均指运维调试视图；线上后台任务接入与面向线上用户的界面收敛仍待完成，见第 00 章的使用场景划分。业务章节通常按「US → 简要设计 → 客户端 → 详细设计 → 服务端配合」展开；核心 A2A 章以运行顺序图为主，第 07 章补充本地约束；第 10 章按接口分组给出请求、响应与失败边界。运行模型按不同场景说明触发条件、参与者交互和最终结果。

运维调试视图的 Skill 列表、包内文件管理、文件级上传、草稿实验和本地完整快照装配已实现。桌面文件落在 `.omnimind-ops/skills`；版本保存方式与当前 LangGraph.js 加载见[Skill 存储与运行加载](../skill-storage-and-loading.md)。运维可在调试桌面的「设置 → 偏好设置」保存并发任务上限（默认 4，范围 1～64），立即用于新任务受理，下调不取消已有任务，详见第 07 章。服务端草稿、发布同步与远端任务交付仍待接入；SQLite checkpoint 已接入；按 thread 诊断导出与上传仍待实现，见第 09 章。

两端的正式版本采用一致相对目录：[Agent 版本文件布局](../agent-version-layout.md)说明提示词、MCP 配置、tool 与 Skill 引用的保存和加载；[Skill 版本文件布局](../skill-version-layout.md)说明完整文件包、内容摘要与标签映射。服务端保存历史全集，客户端按需缓存。

建议串讲顺序：先用版本管理章节说明物料的不可变版本、模型组合指纹及评估回退，再用核心部署章节的单机改造前后图说明职责拆分、跨机接入及 Skill／Prompt 的文件位置，随后用 00 介绍客户端需求与职责，进入核心 A2A 章节的职责图与顺序图讲清 Console → 服务端 Agent → WSS → A2A 任务层 → Agent 执行 → 持久交付的闭环，最后用核心 Skill 章节说明运维能力体系、模板和迭代。阅读页「核心」默认展开，「细节」默认收起，按需展开；手机章节选择也按两组排列。进入细节后，01–03 讲运维维护的能力资源，11 讲本地模型预配置，04 讲 Agent 装配与调试；06–07 串起后台准备、执行和交付结果；09 讲运维诊断，05 讲基础维护更新；最后用 08 分别汇总线上与调试界面的缺口、10 对齐服务端 API。逐章入口保留原编号，Provider 追加为第 11 章，旧章节链接与评论关联不变，也支持直接跳章。

读图约定：US 用例图说明角色与能力；详细设计中的运行模型统一使用顺序图，从上到下表示消息发生顺序。每张图注明前提与结果，不把互斥情况画成连续执行。参与者是运行职责，不代表必须新增独立服务或模块。结构、装配和状态概览只作为简要设计的补充。

核心 A2A 章包含三层职责图与 8 张运行顺序图，统一提供正文 SVG 和可缩放、切换主题的独立 HTML；其余已有顺序图也保留双格式；第 09 章以步骤和场景表说明诊断上传，第 11 章以结构关系图和步骤表说明本地 Provider 流程。新增核心部署章提供单机改造前后图、文件目录图、跨机部署图及 3 张顺序图，描述外部服务端的目标配合方案，未在本仓实现服务端。点击图形查看大图；图示不代表能力已上线。

特别保留的边界：`v.1.0.0` 是 Skill / Agent 的人工发布标签；桌面应用采用其更新规格的 SemVer。复杂 graph 编排随应用代码交付，不纳入 Agent／Skill 的资产版本选择与回退；业务提示词在 Agent 包的 `prompt.md` 中管理，由运行时装配后传入图节点，不内嵌在 graph 定义中。MCP 与 builtinTool 的实现只做兼容性正向优化：MCP 服务不纳入本项目发布版本，builtinTool 随桌面端交付。模型与推理参数不参与 Agent 发布内容 ID，但与固定 Agent／Skill 版本共同生成运行指纹，并保留在运行快照中。正式发布内容 ID、运行指纹、运行快照与执行记录是不同对象；运行指纹及评估回退仍是待实现需求。

依据为当前会话确认内容、Issue #3，以及 2026-10-18 已确认的客户端整包更新规格；旧更新规格中的审批场景不引入本次 MVP。第 09 章补充 2026-10-19 确认的 SQLite checkpoint 与诊断上传；第 10 章统一整理待接入的服务端接口，具体部署地址与超时配置在实施时确定。第 11 章补充截至 2026-10-20 确认并已接入的本地 Provider 首版：管理界面、系统凭据存储、多模型选择与手动连接测试；macOS 凭据存储已验证，Windows 实机验收待完成。本期不新增专门的日志、span 或指标。

图形来源与质量证据位于 `diagrams/` 和 `evidence/`；正文与 SVG 可直接随目录一并分享。完整校验清单见 [交付验收记录](./evidence/验收记录.md)。
