# OmniOps Bots · 客户端 MVP 需求串讲

**我们要构建一个面向运维场景的桌面客户端。** 客户端连接已有内部服务，提供 Agent 与 Skill 的管理、编辑和实验入口，由 Node.js／LangGraph 在本机执行任务，经 Playwright 操作应用管理的外部 Google Chrome；工作台另保留供运维手动操作的内嵌 CEF 浏览器。用户可以主动发起会话，服务端也可以远程调用客户端 Agent；LangGraph 负责流程编排，客户端完成具体操作并回传结果。

核心资产是受版本控制、持续演进的 **Agent 提示词与 Skill**。客户端把提示词、固定 Skill 版本、builtinTool 与 MCP 装配成可执行的 Agent；团队根据真实任务反馈按周迭代发布，保留不可变历史，新版从新会话生效。

[打开逐章串讲入口](./index.html) · [查看完整规格 Issue #3](https://github.com/time-gift24/omniops-bots/issues/3)

本目录围绕客户端的页面、交互、资源管理和任务运行展开，包含 11 章需求与接口设计，以及 1 章前端完成情况。第 10 章集中说明服务端需要提供的 API，第 11 章补充客户端本地 Provider 与模型配置。00、07、08 章的浏览器运行图使用打包客户端实拍，包含实际被 Playwright 操作的内置 CEF 页面；本次使用本地测试模型和测试页面；这些截图记录旧版 Agent CEF 模式，不代表当前外部 Chrome 与手动 CEF 的分工，也不作为多会话并发验收证据。其他资源管理截图保留 Web 演示界面，图片均可点击放大。

串讲时点击阅读页的「本章评论」记录本章意见，可编辑、删除和撤销删除。评论仅保存在当前浏览器，刷新后可继续查看；切换章节保留尚未提交的输入，但刷新前须保存。使用「导出全部评论」生成 Markdown 供会后整理。评论不会上传服务端，清理浏览器数据、换浏览器或移动阅读页路径可能无法再找到原记录，请及时导出。

本仓交付桌面客户端；第 10 章的服务端接口是外部系统配合契约。Node.js 是主后端，Rust 只保留桌面宿主、CEF helper 与 Collector。Node、Playwright、CEF 随包交付，Google Chrome 单独安装和更新；Rust 工具链为 1.92.0。

设计范围包含已具备的界面与尚未完成的能力，具体完成情况见第 08 章。业务章节按「US → 简要设计 → 客户端 → 详细设计 → 服务端配合」展开；第 10 章按接口分组给出请求、响应与失败边界。运行模型按不同场景说明触发条件、参与者交互和最终结果。

Skill 列表、包内文件管理、文件级上传、草稿实验和本地完整快照装配已实现。桌面文件落在 `.omnimind-ops/skills`；版本保存方式与当前 LangGraph.js 加载见[Skill 存储与运行加载](../skill-storage-and-loading.md)。客户端「设置 → 偏好设置」可保存并发任务上限（默认 4，范围 1～64），立即用于新任务受理，下调不取消已有任务，详见第 07 章。服务端草稿、发布同步与远端任务交付仍待接入；SQLite checkpoint 已接入；按 thread 诊断导出与上传仍待实现，见第 09 章。

两端的正式版本采用一致相对目录：[Agent 版本文件布局](../agent-version-layout.md)说明提示词、MCP 配置、tool 与 Skill 引用的保存和加载；[Skill 版本文件布局](../skill-version-layout.md)说明完整文件包、内容摘要与标签映射。服务端保存历史全集，客户端按需缓存。

建议串讲顺序：先用 00 介绍执行底座与整体架构；01–03 讲能力资源，11 讲本地模型接入，04 讲 Agent 装配；06–07 串起准备、执行和交付结果；09 讲故障材料上传，05 讲桌面更新；最后用 08 汇总缺口、10 对齐服务端 API。逐章入口保留原编号，Provider 追加为第 11 章，旧章节链接与评论关联不变，也支持直接跳章。

读图约定：US 用例图说明角色与能力；详细设计中的运行模型统一使用顺序图，从上到下表示消息发生顺序。每张图注明前提与结果，不把互斥情况画成连续执行。参与者是运行职责，不代表必须新增独立服务或模块。结构、装配和状态概览只作为简要设计的补充。

已有顺序图同时提供正文 SVG 和可缩放、切换主题的独立 HTML；第 09 章以步骤和场景表说明诊断上传，第 11 章以结构关系图和步骤表说明本地 Provider 流程。点击图形查看大图；图中服务端消息只说明客户端需要的配合，不扩展服务端内部实现。

特别保留的边界：`v.1.0.0` 是 Skill / Agent 的人工发布标签；桌面应用采用其更新规格的 SemVer。MCP 服务不纳入本项目发布版本，builtinTool 随桌面端交付，模型参数只进入运行快照。正式发布、运行快照与执行记录是不同对象。

依据为当前会话确认内容、Issue #3，以及 2026-10-18 已确认的客户端整包更新规格；旧更新规格中的审批场景不引入本次 MVP。第 09 章补充 2026-10-19 确认的 SQLite checkpoint 与诊断上传；第 10 章统一整理待接入的服务端接口，具体部署地址与超时配置在实施时确定。第 11 章补充截至 2026-10-20 确认的本地 Provider 管理方案；当前桌面仍为单模型配置，管理界面、系统凭据存储和多模型选择待实现，本期不新增专门的日志、span 或指标。

图形来源与质量证据位于 `diagrams/` 和 `evidence/`；正文与 SVG 可直接随目录一并分享。完整校验清单见 [交付验收记录](./evidence/验收记录.md)。
