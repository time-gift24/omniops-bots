# 03 · builtinTool

> 串讲重点：线上用户在服务端 Console 操作，客户端后台执行服务端 Agent 下发的任务并检查所需内置工具；工具选择属于运维调试配置，缺失时回传失败并提示更新客户端。

## US

### 运维调试界面设计

![现有 Agent 工具勾选页签](./assets/screenshots/03-tools.png)

*客户端运维调试工作台实拍，图中使用演示数据；线上客户端仅提供连接状态等基础信息。*

客户端运维调试工作台的 Agent 能力区通过“工具”页签展示并选择 builtinTool，线上用户在服务端 Console 发起业务，不进入该配置页。运行前检查所需工具；缺失时列出工具名称、说明失败原因，并提供桌面更新入口。截图中的“操作前先确认”不属于本期 MVP 流程。

1. 作为运维人员，我为 Agent 选择所需内置工具，让装配明确表达执行需要。
2. 作为线上用户，我在 Console 获知任务因缺少工具失败，按提示完成客户端更新后重新发起业务。
3. 作为线上用户，我在 Console 查看任务结果；运维调试时可在客户端追溯当次工具清单和桌面端版本。

## 简要设计

运维调试工作台在 Agent 的“工具”页签展示可选 builtinTool，保存选定的工具清单；官方装配写入仍须运维权限，本地 Agent 可自由编辑。线上由服务端 Agent 以任务调用客户端，客户端在后台执行。每次运行前，对照已安装桌面版本提供的工具检查装配是否齐全；缺失就结束本次任务，向服务端回传缺失原因供 Console 提示，并通过客户端基础更新入口处理更新。

builtinTool 的实现随桌面应用版本交付，不建立独立工具包发布与同步系统。**Agent 版本固定工具选择；桌面端版本说明实际实现。** 所选 builtinTool 参与 Agent 内容 ID；客户端运行快照记录实际桌面版本和工具清单，不另设工具发布标签。

builtinTool 实现按“只做兼容性正向优化”的基础能力维护，不建立独立的多版本选择或回退体系；这不保证每次升级必然改善任务效果。工具选择变化仍形成新的 Agent 内容 ID，仅实现随桌面升级不改变 Agent 运行指纹，评估时结合实际桌面版本判断，详见[前置 · Agent 版本管理](./前置-Agent版本管理.md)。

## 客户端

- 根据已安装桌面版本提供可用内置工具，执行前检查 Agent 所需工具是否齐全。
- 缺少任一所需工具时直接失败，明确提示缺失原因及更新桌面端；不带着不完整装配开始执行。
- 工具齐全后在后台按 Agent 装配执行，保存工具调用过程并向服务端回传结果；完整过程供客户端运维调试工作台查看。
- 运行快照记录启用的工具清单和桌面端版本；调用状态、错误与起止时间仍放入执行记录。

## 详细设计

### 运行模型一：所需工具齐全

**条件：** 客户端收到一轮任务，按固定的 Agent 装配检查所需 builtinTool。线上由服务端 Agent 下发任务，本地手动调用只用于运维调试；物料准备、其他运行检查均成功，本会话空闲且并发容量可用。

![运行模型：所需 builtinTool 齐全时执行](./assets/runtime/03-builtintool-ready.svg)

[打开交互顺序图：builtinTool 齐全](./diagrams/runtime/03-builtintool-ready.html)

**结果：** 客户端固定运行快照后在后台执行本轮任务，保存过程与结果，并按回传规则返回服务端，供线上用户在 Console 查看；完整过程可在运维调试工作台查看。快照记录当次工具清单与桌面端版本，工具实现由该桌面版本确定。

### 运行模型二：缺少所需工具

**条件：** 运行前发现至少一个 Agent 所需 builtinTool 不在当前桌面版本中。

![运行模型：缺少 builtinTool 时直接失败](./assets/runtime/03-builtintool-missing.svg)

[打开交互顺序图：builtinTool 缺失](./diagrams/runtime/03-builtintool-missing.html)

**结果：** 本轮直接失败，不开始 Chrome 操作。客户端记录缺失工具并向服务端回传失败原因，Console 提示任务失败与更新要求，客户端基础更新入口和运维调试工作台提供对应说明。完成更新后由用户在 Console 重新发起业务，或由服务端 Agent 显式发起新任务；本地调试可手动重试，不自动重跑该失败任务。

Skill 缺失仍按物料同步规则下载完整文件包；builtinTool 缺失通过桌面应用更新解决。桌面版本检查、下载和安装见 [05 · 桌面端更新](./05-桌面端更新.md)。MVP 不增加内置工具独立安装、热更新或单独版本仓库。

## 服务端配合

为支持客户端装配与检查，服务端需要配合：

- 在官方 Agent 物料中提供所需 builtinTool 清单。
- 接收运维人员提交的工具选择变更，按 Agent 发布规则生成新的 Agent ID、保存手填发布标签。
- 远端调用失败时，接收客户端返回的工具缺失结果，决定后续处理。

builtinTool 实现由桌面应用交付，服务端物料同步不单独分发工具实现，也不将其混入 Skill 文件包。
