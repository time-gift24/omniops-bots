# 平台场景实践模板

这是编写实践的结构模板，不是实际业务操作。维护者按具体场景填写后保存为有明确业务含义的文件名，并从平台 `SKILL.md` 的实践索引引用。

## 场景与适用边界

写明任务目标、平台、环境、对象范围、适用条件、不适用条件，以及实践来源和最近验证日期。说明当前方法是已验证实践，还是仍待验证的草稿。

## 输入与操作前检查

逐项定义输入字段、类型、来源和限制；说明如何识别目标对象、环境、账号权限及业务前置状态。缺失或冲突时停止，不以默认值猜测生产对象。

## 操作步骤与加速脚本

按业务顺序写出页面入口、目标识别、动作和观察点；优先采用可观察的页面语义，说明关键控件用途，避免只留下无解释的选择器。

有脚本时写明包内路径、参数及校验、只读或变更性质、影响范围、宿主运行方式、超时和取消行为、产物位置、返回结果、错误类别、是否可重复执行及判断条件。没有稳定脚本时明确“按实践通过 Playwright 操作”，不放空脚本冒充可用能力。

## 成功验证

给出业务结果的检查方法、预期状态与证据位置；区别“请求已提交”和“业务已完成”。需要交接时定义对象稳定 ID、环境、状态、接收平台及字段语义。

## 失败与状态核实

列出常见不适用情况、失败后的状态核实方式和必须停止的条件。脚本失败先检查是否已变更，状态不明就失败，不重复提交；不自动回滚。明确哪些依赖结果缺失会阻止后续平台操作。

## 维护依据

记录来源任务、探索路径、前提、验证结果和已知局限；正式发布前移除凭据及不必要的敏感业务内容。素材与实验产物放在任务工作目录，正式包只保留确认后的通用实践和必要随包资源。
