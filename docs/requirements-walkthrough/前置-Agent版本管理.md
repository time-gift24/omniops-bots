# 前置 · Agent 版本管理：评估与回退的基础

**Agent 的能力由 Skill、系统提示词和模型共同决定。我们需要管理 Skill 的版本、Prompt 的版本，并在运行前根据确定的版本组合与模型选择，自动生成唯一的 Agent 运行指纹。** 这样每次评估、每次线上执行都能回答“用的是哪套能力”，效果变差时也能明确回到哪套组合。

本章是后续资源管理、装配与执行设计的前提；这里的运行指纹是新增需求，不代表当前客户端已实现，也不改变既有 Agent 发布内容 ID 的定义。

本章先明确版本身份与运行指纹；[下一章：服务端部署与持久化](./核心-服务端部署与持久化.md)再用图说明这些物料的存放位置和应用部署：Skill 包保存在 `skills/releases/<skillId>/<contentId>/`，Agent 的 `prompt.md` 与 `agent.json` 保存在 `agents/releases/<agentId>/<contentId>/`。随后再经[客户端总体职责](./00-总体架构.md)，进入[A2A 任务执行](./核心-服务端通过WS调用客户端.md)，说明服务端怎样调用确定版本并交付结果。

## 为什么必须管理版本

同一个 Agent 名称不代表相同的执行能力。修改 Skill 的操作步骤、调整系统提示词，或换用另一个模型，都可能改变任务完成率、输出质量、耗时和成本。如果只记录名称或“最新版”，评估结果就无法归属到确定组合，出现退化也无法选择已验证的历史组合。

版本管理要保留不可变的历史资产；运行指纹要把实际使用的组合与评估结果关联起来。团队才能先比较、再发布，发现退化后显式切回已验证组合，后续仍可继续优化。

## 管理哪些版本

| 对象 | 人可读的指定方式 | 实际固定的内容 |
| --- | --- | --- |
| Skill | `{SKILL}.{Version}`，例如 `巡检规范.v.1.0.0` | Skill 的稳定身份、不可变完整包内容 ID；包括 `SKILL.md`、脚本及参考文件，不只固定入口文本 |
| Agent 系统提示词（Prompt） | `{AgentName}.{Version}`，例如 `巡检Agent.v.1.0.0` | 指定 Agent 版本中的完整系统提示词；沿用 Agent 发布标签与内容 ID，不另建独立 Prompt 标签体系 |
| 模型 | 确定的 Provider 接入身份与模型 ID；服务商支持时指定模型快照／修订 | 本次实际选择的模型及有效推理参数；接入地址使用非敏感身份表示，不包含密钥 |

名称与版本写法便于阅读，实际装配必须解析到稳定资源身份与内容 ID，不能仅按名称匹配，也不能在执行时重新解释为“最新版”。一个 Agent 可以引用多个 Skill，每个引用均固定版本及挂载路径。

提示词随 Agent 版本管理：只改 Prompt 就发布新的 Agent 版本；改 Skill 就发布新的完整包，并联动更新受影响 Agent 的固定引用与版本。已发布标签与内容不可覆盖；草稿实验没有正式标签，仍须固定当次完整内容快照，才能与其他实验比较。

## 复杂 graph 只负责编排，提示词在图外管理

**复杂 graph 的编排不参与本章的 Agent／Skill 资产版本管理。** 节点、连线、条件分支、状态流转和并发控制属于运行实现，随服务端或桌面应用代码交付，沿用源码与应用发布管理；不另建 graph 的资产标签、历史图选择或编排回退体系。仅修改编排不会自动发布新的 Agent／Skill 版本，也不将编排代码纳入 Agent 内容 ID 或本章定义的运行指纹。

**业务提示词不写在 graph 中。** 完整系统提示词保存在确定 Agent 版本的 `prompt.md`，与 `agent.json` 一起固定；运行时先解析版本、读取提示词和 Skill 包，再把装配好的指令／Agent 传给图节点。节点、路由函数和图定义不内嵌或另存一份可独立修改的业务 Prompt 正文，修改提示词必须走原有 Agent 发布流程。

复杂图中的不同节点可以调用不同 Agent，但每个调用都显式使用确定的 Agent／Skill 版本，复用各自版本包中的提示词。图负责“何时调用、如何衔接”，版本物料负责“调用哪套能力”；任务输入和所需上下文继续显式传入，不靠改写图内提示词或读取浮动最新版来切换能力。

## 自动生成 Agent 运行指纹

**运行指纹 = 对“固定 Skill 版本集合 + 指定 Agent 系统提示词版本 + 实际模型选择”规范化后计算的内容摘要。** 同一组合生成相同指纹；任一 Skill 版本、Prompt 版本或模型选择发生变化，生成不同指纹。指纹由客户端在装配成功、执行开始前自动生成，无需人工填写。

![版本组合如何生成 Agent 运行指纹](./assets/preface-fingerprint.svg)

[打开交互图：版本组合如何生成 Agent 运行指纹](./diagrams/preface-fingerprint.html)

| 指纹输入 | 固定规则 |
| --- | --- |
| Agent 版本 | 使用稳定 Agent ID 与正式内容 ID；内容 ID 已覆盖系统提示词和装配配置。草稿实验使用本次不可变内容快照摘要 |
| Skill 版本集合 | 逐项包含 Skill ID、内容 ID 和挂载路径，按固定字段顺序排序；本地编辑内容先捕获完整快照，不使用浮动引用 |
| 模型选择 | 包含 Provider 的非敏感接入身份、模型 ID、可取得的模型快照／修订，以及实际生效的推理参数；仅改变本机展示名或轮换密钥不改变指纹 |
| 摘要规则 | 固定指纹格式版本，使用规范化 JSON 与 SHA-256；对象键排序，Skill 集合按固定顺序排列，明确参数默认值，保留完整摘要作为身份 |

例如，`巡检规范.v.1.0.0 + 巡检Agent.v.1.0.0 + 模型A` 对应指纹 F1；只把 Skill 换为 `v.1.1.0` 后产生 F2；在 F2 的资产组合上换成模型 B，又产生 F3。每个指纹都保留其组成清单，界面可展示缩写，不能仅保存一个无法解释的哈希。

必须区分以下三个对象：

- **Agent 发布内容 ID**：标识不可变的 Agent 包，沿用现有算法；模型不进入发布包，改模型无需重新发布 Agent。
- **Agent 运行指纹**：在确定 Agent／Skill 版本后，再结合实际模型与参数生成，用于评估分组和选择回退组合。
- **运行快照与执行记录**：快照保留实际工具、MCP、桌面版本等运行条件；每次执行仍有独立 runId。同一指纹可以执行多次，输入、输出和执行 ID 不进入该指纹。

指纹标识确定的配置组合，不保证模型每次输出一致。模型别名若由服务商更新且无可固定修订，或远端 MCP 实现、graph 编排代码发生变化，即使指纹相同，行为仍可能变化；评估时须同时核对实际图标识、应用／服务端构建版本、运行快照与评估时间，不能宣称完整环境可重现。

## 如何支持评估与回退

后续将根据具体 Skill 的任务目标、操作场景与输出要求，分别构建测试集，覆盖典型任务、边界情况和失败场景，并明确输入、预期结果与判定口径，用于比较不同版本组合的效果和回归验证。测试集建设不在本次范围内，本次仅明确后续方向，不制作测试集或实现自动化评估。

![从版本评估到显式回退](./assets/preface-evaluation-rollback.svg)

[打开交互图：从版本评估到显式回退](./diagrams/preface-evaluation-rollback.html)

1. **准备评估**：固定评估用例、输入与判定口径，为每个候选组合生成指纹；尽量每次只改变一个因素，区分 Skill、Prompt 或模型带来的影响。
2. **记录结果**：每次评估及正式执行关联运行指纹与组成清单；评估结果按指纹归集，结合运行快照对照完成率、质量、耗时和成本，缺失数据不补零。
3. **选择发布组合**：运维根据评估与业务反馈选择明确版本和模型，保留历史组合与评估依据；发布新版本不覆盖旧包，也不改变已有会话快照。
4. **显式回退**：发现退化后，选择已验证指纹对应的 Agent／Skill 历史版本及模型参数，为新会话或新任务恢复该组合。先检查物料可取得、模型可用及当前工具兼容；无法恢复时明确失败，不静默替换模型或版本。

回退不改写历史标签，不改变正在运行的任务，不自动重跑失败或取消的请求；需要再次执行时显式创建新 Run。回退范围是上述资产与模型组合，不承诺撤销业务操作或恢复旧 graph 编排、旧 MCP／旧桌面工具实现。

## MCP 与 builtinTool：只做正向优化

**本项目将 MCP 与 builtinTool 视为持续做正向优化的基础能力，不为其实现建立与 Skill／Prompt 相同的多版本选择、评估回退体系。** 正向优化指在保持既有调用契约兼容的前提下修复问题、提高稳定性与效率；这是维护要求，不是对每次变更一定提升效果的保证。

| 基础能力 | 演进方式 | 与 Agent 指纹的关系 |
| --- | --- | --- |
| MCP | 由远端服务持续维护实现，不纳入本项目发布版本，不提供历史实现切换 | Agent 选择的完整非敏感连接配置仍参与 Agent 发布内容 ID；远端实现升级本身不生成新的 Agent 运行指纹，实际能力清单记录于运行快照 |
| builtinTool | 实现随桌面应用更新交付，不另设独立工具版本仓库、安装或回退入口 | 所选工具 ID 仍参与 Agent 发布内容 ID；仅实现随桌面升级不生成新的 Agent 运行指纹，实际桌面版本与工具清单记录于运行快照 |

正向优化不能静默删除既有能力或破坏参数、返回值与错误语义。发生不兼容变化时，应先完成兼容处理或明确调整 Agent 装配并重新验证；工具缺失、连接失败仍按现有边界明确失败。选择哪些工具、连接哪个 MCP 属于 Agent 装配，修改这些选择仍形成新的 Agent 内容 ID，并改变运行指纹。

本章仅补充需求和职责边界，不新增日志、span 或指标；运行指纹的保存、评估结果关联与回退入口仍待实现。资产发布和装配见 [01 · SKILL](./01-SKILL.md)、[04 · Agent](./04-agent.md)，工具边界见 [02 · MCP](./02-MCP.md)、[03 · builtinTool](./03-buildintool.md)，本机模型选择见 [11 · Provider](./11-Provider.md)。
