# 核心 · 服务端通过 WebSocket 调用客户端

**用户在服务端 Console 发起业务；服务端 Agent 经 WebSocket 调用确定版本的客户端 Agent；客户端在本机后台执行并回传结果，服务端确认接收后继续业务。** 客户端主动连接服务端，任务不依赖打开本地调试桌面。

本章集中说明线上调用主链路，沿用 [10 · 服务端 API](./10-服务端API.md) 的既有契约。WebSocket 通道及远端任务接入仍待实现，本地调试能力已具备不代表线上链路已经完成。

## 谁负责什么

| 参与者 | 职责 |
| --- | --- |
| 线上用户与 Console | 发起业务、查看状态和结果；需要人工登录时按提示处理，再显式发起新任务 |
| 服务端 Agent | 编排业务，选择目标客户端与官方 Agent 确定版本，下发调用或取消，消费最终结果 |
| 客户端 Node.js runtime | 维护连接，校验和去重调用，准备固定物料与运行快照，执行图、模型、MCP 和 Chrome 操作，持久保存结果并补传 |
| 运维调试桌面 | 编辑与发布资产、本地实验、预配置模型、查看过程和诊断；这些操作服务于主链路 |

客户端由 Tauri 提供原生宿主，业务执行由 Node.js／LangGraph 承担，Playwright 操作应用管理的外部 Google Chrome。运维手动使用的内嵌 CEF 与 Agent 页面分开管理。

## 一次调用怎样完成

1. **连接与鉴权**：后台客户端以现有身份主动建立 `WSS /api/clients/connect` 长连接。服务端校验用户、组织和安装身份，协商协议版本、桌面版本与可用工具；确认连接可用后才投递任务。凭据不放 URL 查询串。
2. **下发调用**：用户在 Console 发起业务，服务端 Agent 发送 `task.call`，包含唯一 `callId`、目标客户端、官方 `agentId` 与 `agentContentId`、业务 `input`、`context` 和调用有效期。任务正文不传密钥，也不覆盖本机 Provider／模型选择。
3. **去重与受理**：客户端先查持久去重记录，再检查权限、有效期及并发容量；新调用受理记录落盘后返回 `task.accepted`，给出 `threadId`、`runId`。受理只表示接下任务，不能作为业务完成凭据。
4. **准备与执行**：后台按指定版本经 HTTPS 补齐缺失 Agent／Skill 包，固定快照，检查 MCP 和内置工具，使用本机预配置模型执行。每次调用创建独立会话与 Chrome 页面；按准备、执行、停止阶段回传 `task.status`。运行指纹按前置章节的新增需求生成，尚待实现。
5. **保存并发送结果**：执行结束后，客户端先持久保存终态和结果，再发送 `task.result`，携带原 `callId`、稳定 `resultId`、结果摘要、业务结果或安全错误、起止时间与运行快照。
6. **确认交付与继续业务**：服务端幂等持久保存结果及索引后，返回匹配 ID 和摘要的 `task.result-ack`。客户端校验后才标记已交付；服务端 Agent 消费结果、继续业务，Console 展示状态与结果。

**连接成功、任务已受理、任务执行结束、结果已交付是四个不同边界。** WebSocket 发送成功或心跳正常不能代替结果 ACK；最终结果也不能由一条模型输出结束来判定。

## WebSocket 与 HTTPS 各传什么

| 通道 | 承载内容 | 详细契约 |
| --- | --- | --- |
| WebSocket | 调用、受理、任务级状态、取消及其回执、最终结果与结果 ACK | [10 · 服务端 API：WebSocket](./10-服务端API.md#websocket调用取消结果和确认) |
| HTTPS | 官方版本清单、完整物料包、草稿发布、桌面更新及显式诊断上传 | [10 · 服务端 API](./10-服务端API.md) |

正常任务通道不持续上传逐条模型正文、完整工具过程或 checkpoint，也不传 Skill 文件包、浏览器 profile 或 CDP 端口。完整过程留在本地供运维查看；需要诊断时按 [09 · 运维与诊断上传](./09-运维与诊断上传.md) 显式准备和上传。

## 异常时仍守住哪些边界

| 情况 | 处理结果 |
| --- | --- |
| 重复投递同一个 `callId` | 返回已知受理状态或原结果，不重复开始模型、MCP 或 Chrome 操作；同 ID 不同调用内容拒绝为冲突 |
| 客户端忙或调用不可受理 | 返回明确拒绝，不进入本地队列；服务端决定再次执行时使用新 `callId` |
| 网络断开但进程仍在 | 当前任务继续，客户端有界退避重连；重新鉴权后补传未 ACK 的原结果，不重新执行 |
| 客户端重启 | 已完成结果继续交付；未完成任务记为 `interrupted-unknown`，不根据 checkpoint 自动续跑 |
| 取消或超时 | 停止后续步骤，等待已发起操作排空并保存终态；取消回执不表示已经停止，已发生的外部操作不回滚 |
| 所需版本、模型、工具不可用或需要人工登录 | 明确失败并回传原因；不静默换版本、换模型或削减能力，处理后显式发起新任务 |

执行结束与交付确认分开保存；服务端重复收到相同结果返回同一 ACK，不重复驱动后续业务。调用去重不等于承诺外部系统的副作用恰好发生一次。
