# 11 · Provider：本地模型接入与选择

> 串讲重点：用户在客户端维护多个 OpenAI 兼容接入，每个 Provider 配置多个模型；新会话选择确定的模型，凭据留在本机，配置不可用就明确报错。

**本章首版已接入：Provider 管理、系统凭据存储、多模型选择与手动连接测试。** Node.js runtime 通过 `@langchain/openai` 的 `ChatOpenAI` 使用明确的本地配置；macOS 凭据存储已验证，Windows 实机验收待完成。

## US

### 界面设计

在客户端设置中提供 Provider 管理入口：列表展示名称、接入地址、鉴权是否已配置和模型数量；详情支持新增、编辑、删除 Provider，手动维护模型列表、设置全局默认模型，并选择一个模型手动测试连接。密钥只显示“已配置／未配置”，提供替换和清除操作。

新会话入口默认选中全局默认的 Provider＋模型，开始前允许改选；开始后展示本会话的固定选择。测试结果属于设置页面的接入检查，不生成 Agent 会话或浏览器操作记录。本章不使用演示截图代替已完成界面的证据。

1. 作为用户，我能配置多个接入地址，并在每个 Provider 下维护多个实际模型名称。
2. 作为用户，我能为需要鉴权的服务配置 API Key，也能连接无鉴权服务；密钥保存在本机操作系统凭据库。
3. 作为用户，我能设置默认模型，在新会话开始前改选，并明确知道本次实际使用哪个 Provider 和模型。
4. 作为用户，我能手动测试指定模型的接入，看到明确结果；保存配置不会自动发起模型请求。
5. 作为使用者，我能区分配置、凭据和调用失败；失败不会让客户端自动切换到另一个 Provider 或模型。

### Provider 与模型的关系

Provider 是一个具名接入，首版统一使用 **OpenAI Chat Completions 兼容接口**，允许自定义 base URL。名称在本机配置内唯一；相同地址可以因使用不同凭据配置为不同 Provider。每个 Provider 下手动填写多个上游实际 `model` 名称，不自动拉取模型列表。

| 配置项 | 保存内容与校验 |
| --- | --- |
| Provider 名称 | 非空、在本机配置内唯一，用于展示与选择 |
| 接入地址 | 绝对 HTTP／HTTPS base URL，保留路径前缀，例如 `https://gateway.example/v1`；不允许 URL 用户信息、查询参数或片段携带凭据 |
| 协议 | 首版固定为 OpenAI Chat Completions 兼容接口，不因供应商名称自动切换协议 |
| 鉴权 | 可选 API Key 的本地凭据引用；未配置时不发送认证头，已配置时使用 `Authorization: Bearer <key>` |
| 模型列表 | 手动维护实际 `model` 名称，保留大小写；不允许空名或同一 Provider 内重复，不同 Provider 下允许同名模型 |
| 全局默认模型 | 一个明确的 Provider＋模型组合；必须能在本地配置中解析，不以列表第一项作为隐式默认值 |

客户端按配置的 base URL 连接模型服务或内部网关，不经过本项目服务端转发。地址无效时不发送请求；HTTPS 保留正常证书校验，路径前缀不能被固定地址或重复拼接的版本路径覆盖。首版不增加原生 Anthropic／Gemini 协议、自定义认证头或 OAuth。

### 凭据的本地边界

普通配置文件只保存凭据引用，API Key 值写入操作系统凭据库。新增时留空表示无鉴权；编辑已有配置时明确区分保留、替换和清除，避免把未回显的密钥当作空值误删。清除后移除凭据引用，后续请求不再发送认证头。

**主动选择无鉴权与凭据读取失败是不同状态。** 配置仍有引用，但凭据缺失、库被锁定或访问被拒绝时，停止测试或调用，不降级成无鉴权请求。保存或凭据写入失败时保留输入和原有效配置，不把未完成的修改显示为已保存。

密钥值不进入 Agent 发布包、内容摘要、运行快照、普通配置导出、诊断包或遥测；界面和错误信息不回显密钥、原始认证头或上游响应正文。凭据引用由本地解析，不通过服务端下发密钥。

### 默认模型与会话固定

新会话在开始前使用全局默认值，用户可以改选其他 Provider＋模型。开始时固定实际 Provider、模型、协议、接入地址和非敏感运行参数；这些属于运行条件，不参与 Agent 内容 ID 或发布标签。

修改默认值只影响新会话。已有会话不重新绑定到同名的新配置，也不因为修改设置而切换正在执行的模型。后续调用仍使用固定运行条件；固定配置或所需凭据不可用时明确失败，保留已有会话内容，不自动选择其他接入。删除默认模型或其 Provider 后，要求重新选择默认值，不自动补成其他模型。

固定运行条件不代表把密钥复制进快照，也不保证外部模型服务行为永远不变。运行快照只记录非敏感选择；凭据值通过本机凭据边界取得。与 Agent 装配的关系见 [04 · Agent](./04-agent.md)。

## 客户端

- 提供本地 Provider 新增、编辑、删除与模型增删，展示空列表、保存中、保存失败和凭据不可用状态。
- 设置一个全局默认模型；新会话开始前可改选，开始后展示实际固定选择。未配置默认值且没有明确选择时，提示配置或选择模型。
- 用操作系统凭据库保存可选 API Key；普通配置只保存引用，列表和详情不读取并回显已有密钥。
- 仅在用户选择模型并点击“测试连接”时发起检查；保存配置、打开页面和切换模型不自动测试。
- 测试期间显示进行中，支持结束本地等待；展示本次 Provider、模型和结果。配置修改后，旧结果不能作为新配置已测试的证明。
- 配置不可用、鉴权失败、超时或断流均明确报错；不自动切换 Provider、模型，不自动重发整次请求。

## 详细设计

### 运行模型一：保存本地接入

| 步骤 | 客户端行为 | 结果或失败边界 |
| --- | --- | --- |
| 1. 编辑 | 填写名称、base URL、模型列表，按需设置 API Key | 未保存内容保留在编辑状态，不立即影响已有配置 |
| 2. 校验 | 检查空值、重复名称、地址和默认模型引用 | 失败指出字段，不访问模型服务 |
| 3. 保存 | 有 Key 时写入系统凭据库，配置仅保存引用；无 Key 时不创建鉴权引用 | 任一步失败显示未保存，保留原有效配置和编辑输入 |
| 4. 完成 | 更新本地 Provider 和可选模型列表，显示已保存 | 不自动测试、不发起模型请求，不生成 Agent 或 Skill 发布版本 |

### 运行模型二：手动测试指定模型

**条件：** 用户在 Provider 详情选择已配置模型并点击“测试连接”。有修改时先保存，避免测试对象与已保存对象不一致。

| 步骤 | 客户端行为 | 结果或失败边界 |
| --- | --- | --- |
| 1. 固定测试对象 | 取得本次 Provider、模型、地址和鉴权状态 | 编辑不改变已经发出的请求 |
| 2. 取得鉴权 | 无引用则不添加认证头；有引用则读取 Key 并添加 Bearer 头 | 凭据不可用时在发送前失败，不发送无鉴权替代请求 |
| 3. 发送最小请求 | 对指定模型发送固定、最小的文本请求，并设置 15 秒总超时 | 不读取会话、提示词、Skill 或 MCP 配置，不装配工具、不占用浏览器执行入口 |
| 4. 展示结果 | 校验响应正常结束，显示成功或脱敏失败类别 | 超时、取消或未完成响应不能显示成功；不自动重试，不保存回复正文作为会话 |

测试成功只说明这次模型请求成功，不代表支持全部工具、图像或扩展参数。界面区分字段无效、保存失败、凭据不可用、连接／TLS／超时、上游拒绝和响应不完整；能依据结构化上游错误确定时，再展示鉴权失败、模型不可用或限流等类别，不仅凭 HTTP 404 断定模型不存在。

取消只结束本地等待，不承诺上游计算已经停止；测试取消或失败不会触发 Agent、工具、浏览器任务或自动重发。

### 运行模型三：新会话选择与后续使用

| 场景 | 客户端处理 |
| --- | --- |
| 有有效全局默认值 | 新会话预选默认组合，开始前允许明确改选 |
| 无默认值或默认组合不可用 | 提示配置或选择有效模型，不任意选一个模型开始 |
| 开始会话 | 固定实际模型运行条件，按第 04 章完成 Agent 装配；失败不进入模型或工具执行 |
| 会话后续轮次 | 沿用固定选择；修改全局默认值不影响该会话 |
| 原配置或凭据不可用 | 保留历史和固定选择，显示错误，不把历史发送给其他 Provider 或模型 |

### 验收与观测边界

1. 验证两个 Provider 及各自多个模型，包括不同 Provider 下的同名模型；实际请求使用正确地址、路径前缀和 `model`。
2. 验证有 Key 的 Bearer 头、无 Key 时无认证头、已有引用无法读取时不发送请求；普通配置、快照和诊断材料均无密钥值。
3. 验证字段错误、保存失败和凭据库访问失败后，原有效配置和输入保留，没有半完成的成功状态。
4. 验证手动测试不读取会话、不执行工具，保存时不自动测试；超时、取消、上游拒绝和断流不误报成功或自动重发。
5. 验证默认值持久保存、新会话改选、开始后固定，以及配置不可用时不自动切换；修改设置不改变正在执行的请求。

Provider 管理与连接测试首版不新增专门的日志、span 或指标：界面的操作状态、测试结果与稳定的脱敏错误类别满足本期排查和验收。模型生成调用的观测继续遵循已有规范，密钥、认证头、提示词与回复正文不写入遥测。

### 当前实现与接入缺口

已接入 [Provider 设置页](../../web/src/components/settings/provider-settings.tsx) 与 [ProviderSource](../../web/src/providers/source.ts)：可新增、编辑、删除接入，维护多个模型，设置全局默认值，并手动测试已保存模型；新会话开始前可改选，开始后固定。保存不触发测试；测试支持取消，不读取会话或执行工具。

[Node.js Provider 模块](../../desktop/runtime/providers.mjs) 将配置原子保存到 `providers.json`，凭据字段只含 UUID 引用；[凭据 IPC](../../desktop/runtime/credentials.mjs) 连接 [原生凭据边界](../../crates/omniops-bots-desktop/src/credentials.rs)，分别使用 macOS Keychain 与 Windows Credential Manager。macOS 隔离 Keychain 验证已通过；Windows 尚未实机验证。无 Key 时不发送认证头，有引用但无法读取时明确失败，不自动降级或重试。

兼容迁移仅在 `providers.json` 不存在时导入旧环境变量／`model.env`；原文件保留，不自动删除，导入后由用户自行管理旧文件中的敏感内容。新配置读取失败可重试，不回退到旧单模型。缺少 Provider 快照的旧会话仍可查看，但须新建会话才能运行。完成情况见 [08 · 前端现状与缺口](./08-前端现状与缺口.md)。

## 服务端配合

首版 Provider 配置和凭据由客户端本地管理，无需本项目服务端提供配置下发、凭据托管、模型发现或模型请求转发接口。接入地址可以指向既有内部网关，网关按自身约定提供 OpenAI 兼容服务。

已有服务端契约见 [10 · 服务端 API](./10-服务端API.md)。远端任务接入时也不能通过任务正文携带密钥或要求客户端自动切换其他模型。
