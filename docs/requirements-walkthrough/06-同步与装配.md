# 06 · 同步与装配：清单先行、物料按需

> 串讲重点：客户端在新会话开始前核对版本、补齐缺包，再按 Agent 清单装配；准备失败就停止本次运行。

## US

### 界面设计

新会话入口展示准备过程：核对版本、下载缺失物料、检查工具、准备完成或失败。资源详情展示版本与本地缓存情况。已有会话继续使用开始时的快照；同步到的新版本从新会话生效。

1. 作为用户，我希望新会话使用同步后的官方资源，已有会话继续使用开始时的快照。
2. 作为用户，我希望客户端接到远端调用后先核对指定 Agent 版本，避免使用其他版本替代。
3. 作为用户，我希望只下载当前所需物料，并保留已下载的 Skill 版本轨迹。
4. 作为使用者，我希望同步或工具检查失败时看到明确原因，以便处理后重新发起。

![同步用例图：同步清单、获取缺失物料、按指定装配运行](./assets/06-sync-usecase.svg)

## 简要设计

客户端同步分两步：先获取版本清单，再按当前 Agent 的装配清单补齐缺失物料。不会为了同步清单下载全部历史包。官方资源按版本保存在本地，旧包不自动覆盖或清理；运行时选择对应版本装配。

HTTPS 负责清单和物料传输。WebSocket 负责调用和结果，不承担文件包同步。未上传的本地草稿可以直接实验，运行前固定完整快照，不要求先上传为官方版本。

### 服务端版本库与客户端缓存一一对应

| 同一个版本 | 服务端 | 客户端 |
| --- | --- | --- |
| 完整文件包 | `<服务端根>/skills/releases/<skillId>/<contentId>/` | `<客户端根>/skills/releases/<skillId>/<contentId>/` |
| 标签索引 | `skills/releases/<skillId>/tags.json`，由正式发布新增映射 | 相同相对路径，只接受服务端确认的映射 |
| 包内路径与内容 | `SKILL.md`、引用文件、脚本和资源原始字节 | 相同路径、相同字节，下载后独立核对摘要 |

两端的物理根路径可以不同，版本相对路径不变。客户端只缓存当前需要的包，不镜像全部历史；标签清单可以包含尚未缓存的版本。完整包先在正式版本目录外暂存，通过摘要和来源校验后再提交；版本包内不增加发布元信息或传输清单。详细目录及失败处理见 [Skill 版本文件布局](../skill-version-layout.md)。

## 客户端

- 官方新会话同步版本清单；每次远端调用核对所需版本，不匹配或缺少物料就先同步。
- 按清单下载缺失 Skill 包及其他 Agent 物料，复用本地已有的相同版本；同步失败则本次调用失败，不降级到旧版。
- 运行前检查所需 builtinTool；缺失时提示更新桌面端，不尝试通过 Skill 同步安装内置工具。
- Skill 文件固定保存在当前用户主目录下的 `.omnimind-ops/skills`（macOS 为 `~/.omnimind-ops/skills`）。本地可编辑包与官方版本缓存分开；Windows 当前同样使用用户主目录，不硬编码盘符。

当前已接入本地文件持久化、官方缓存完整包摘要校验和会话固定快照；服务端清单、完整包下载与来源验证仍待接入。目录、内容 ID 与人工标签的对应关系，以及当前 LangGraph.js 加载路径见[Skill 存储与运行加载](../skill-storage-and-loading.md)。

## 详细设计

### 运行模型一：所需版本已在本地

**条件：**用户发起官方 Agent 新会话；客户端从服务端核对版本清单后，发现本次所需完整物料都已缓存。远端调用也执行相同核对，但以服务端指定的 Agent 版本为准。

![缓存命中运行顺序：核对清单、检查缓存、固定装配](./assets/runtime/06-cache-ready.svg)

[打开运行模型](./diagrams/runtime/06-cache-ready.html)

**结果：**相同版本不重复下载。客户端检查 builtinTool 并固定运行快照后，才进入执行流程；本地有旧包不代表可以跳过所需版本的核对。

### 运行模型二：下载本次缺失的物料

**条件：**版本清单已明确本次装配，但本地缺少其中某些完整 Skill 包或其他 Agent 物料。本图只展示下载成功的情况。

![按需下载运行顺序：清单核对、识别缺失、下载保存、固定快照](./assets/runtime/06-download-missing.svg)

[打开运行模型](./diagrams/runtime/06-download-missing.html)

**结果：**客户端只下载缺失项，按版本保存后装配。MCP 配置或引用与 Agent 一并准备；旧 Skill 包继续保留，不自动覆盖或清理。已有手动会话继续使用原快照，同步取得的新版只用于新会话。

### 运行模型三：核对或下载失败

**条件：**核对清单失败，或者下载所需物料失败、物料不可取得。任一条件都直接结束本次准备，不再继续后面的装配与执行。

![同步失败运行顺序：请求失败、保留缓存、反馈本次失败](./assets/runtime/06-sync-failure.svg)

[打开运行模型](./diagrams/runtime/06-sync-failure.html)

**结果：**客户端展示明确原因，本次调用失败，不降级到旧版，不使用不完整装配。远端调用按原调用 ID 记录并回传失败；本地已有缓存与未同步编辑保留。用户或服务端处理原因后重新发起。

物料齐备但缺少所需 builtinTool 时同样不能执行：客户端提示更新桌面端，不通过 Skill 同步补装内置工具，具体顺序见[builtinTool](./03-buildintool.md)。未上传的本地草稿实验直接固定完整快照，不要求先经过官方同步。

MVP 不引入 Git 仓库、全量历史镜像或自动清理机制。Skill 磁盘布局已确定：本地包位于 `local/<localId>`，两端官方完整版本均位于 `releases/<skillId>/<contentId>`；会话完整包快照另存 `.omnimind-ops/runs/<sha256(threadId)>/skills/<mountName>/`。准备完成后的运行互斥、结果补传和重启恢复见[任务执行与恢复](./07-任务执行与恢复.md)。

## 服务端配合

为支持客户端核对版本与按需装配，服务端需要：

- 提供官方已发布 Agent、Skill 的版本清单和缺失物料下载；Agent 的 MCP 配置或引用随清单关联。
- 使用与客户端相同的 Skill 版本相对目录、包内路径、内容 ID 算法及标签映射；只有完整包与关联 Agent 均可取得后才公布正式发布结果。
- 远端调用明确所需 Agent 版本，客户端据此核对；具体字段和端点留到实现阶段确定。
- 保留已发布版本和标签的不可变关系。Skill 发布产生新 Agent 装配，不改写历史版本。
- 按现有身份体系开放相应读取和运维写入能力，不新增客户端账号体系。
